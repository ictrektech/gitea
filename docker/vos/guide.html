从 VOS 打开应用后自动登录。首次访问优先使用 VOS 用户名创建独立 Gitea 账户。旧版自动生成的用户名会在下次登录时迁移到可用的用户名，仓库和凭据继续保留；请按仓库页面更新克隆地址。之后按 VOS 的稳定用户 ID 同步显示名、管理员角色与语言；VOS 中改名不会改变仓库归属。普通用户仅能访问自己或被授权的仓库，系统管理员拥有 Gitea 管理权限。

调用 API

外部客户端可以使用原生 Gitea PAT，或使用 VOS 为 com.ictrek.gitea 签发的用户 access token。通过 VOS OAuth2 authorization code + PKCE 获取，令牌到期后按 VOS OAuth2 流程刷新。浏览器插件可调用 window.vos_platform.api.v1000.oauth2.authorize() 和 token()，并校验 state。不要将令牌写入仓库或日志。

export GITEA_URL='https://<VOS地址>:1180/app/com.ictrek.gitea'
# VOS_ACCESS_TOKEN 由你的 OAuth2 客户端提供
curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user"

curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user/repos"

创建仓库：POST /api/v1/user/repos，JSON 示例 {"name":"demo","private":true,"auto_init":true}。仓库默认私有。更多接口使用上方 Swagger，路径前缀始终为 /app/com.ictrek.gitea。

Git HTTPS

使用页面给出的 HTTPS clone URL；用户名填写 Gitea 用户名，密码可使用原生 PAT 或 VOS access token。建议使用系统凭据管理器，不把令牌写入 URL。Git LFS 保留 Gitea 原生协议。浏览器登录统一走 VOS，无需第二套登录密码。

原生 PAT 与 SSH 密钥

在用户设置 → 应用创建个人访问令牌，选择所需权限；令牌只显示一次。在用户设置 → SSH / GPG 密钥添加自己的 SSH 公钥，私钥留在客户端。

# GITEA_TOKEN 为你自己创建的原生 PAT
curl --fail -H "Authorization: token $GITEA_TOKEN" \
  "$GITEA_URL/api/v1/user"

# 默认 SSH 端口为 32222，用户名固定为 git
ssh -T -p 32222 git@<VOS设备IP或域名>
git clone ssh://git@<VOS设备IP或域名>:32222/<仓库所有者>/<仓库名>.git

SSH 独立于宿主机管理用的 22 端口，安装参数可调整端口与外部域名；仓库页面会生成 clone 地址。首次使用先访问一次代码管理完成 VOS 账户创建。VOS 关联账户的 PAT 和 SSH 操作会通过应用专属平台凭据查询该用户的最新状态；用户被禁用、删除或平台校验不可用时拒绝访问。PAT 与 SSH 密钥也可分别在 Gitea 中撤销；VOS 退出浏览器会话不等于撤销这些长期凭据。

MCP 与 AI Agent

应用同时运行官方 gitea-mcp 服务，在 /app/com.ictrek.gitea/mcp 提供无状态 HTTP 端点；同一 VOS 网络内使用 http://gitea:8080/app/com.ictrek.gitea/mcp。端点由网关校验凭据，必须携带 Authorization，值为 VOS access token 或自己的 Gitea PAT；网关只接受 Bearer、token、Basic 三种写法，前两种等价；无凭据或凭据无效时返回 401。服务端不保存令牌，权限按该用户生效。只开放 repository、file、branch、pull_request、issue 五类工具；创建仓库需要 PAT 包含 write:user。不要附加不匹配的 Origin 头，跨站来源会被拒绝。

# 先在“用户设置 → 应用”创建 PAT，然后初始化 MCP 会话
curl --fail -X POST "http://<VOS设备IP或域名>:1180/app/com.ictrek.gitea/mcp" \
  -H "Authorization: Bearer $GITEA_PAT" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

Actions 与 Runner

Actions 已开启。外部 Runner 使用前，请在安装配置“Gitea 对外访问地址”填写完整的 VOS 可达地址，供 checkout、任务 API 与 Webhook 使用；默认值适合同一 VOS 网络。先在仓库设置启用 Actions，再从“仓库 / 组织 / 用户 / 实例设置 → Actions → Runners”取得相应作用域的注册令牌。实例级 runner 需要管理员权限。Runner 在构建机独立运行，不会自动占用 VOS 容器的构建环境。

mkdir -p ~/dev/build/gitea-runner
cd ~/dev/build/gitea-runner
# 先安装 Gitea Runner 5.x；将注册令牌存入仅自己可读的文件
gitea-runner register --no-interactive \
  --instance "$GITEA_URL" \
  --token-file "$HOME/.config/gitea/runner-token" \
  --name vos-runner --labels 'vos-linux:host'
gitea-runner daemon

--instance 必须包含 /app/com.ictrek.gitea/，并能被 runner 和任务环境访问；同一 VOS 网络可用 http://gitea:8080/app/com.ictrek.gitea/。外部机器使用 VOS 的 HTTPS 地址并信任其证书。示例 host 标签直接在 runner 环境执行，仅用于可信仓库；需要容器隔离时按官方 Runner 文档配置 Docker 标签。持久保存 .runner，它包含机器凭据。

仓库中添加 .gitea/workflows/ci.yml：

name: CI
on: [push, workflow_dispatch]
jobs:
  verify:
    runs-on: vos-linux
    steps:
      - uses: builtin:checkout
      - run: echo 'VOS Gitea Actions ready'

注册令牌用于新增 runner，机器凭据用于轮询任务，均不同于用户 PAT。注册后的 runner 按仓库 / 组织 / 实例作用域独立管理，不随浏览器退出而停止；撤销时需在相应 Runners 页面禁用或删除 runner，必要时重置注册令牌。任务与 Secrets 的权限遵循 Gitea 原生规则。

公共目录与备份

安装时在“Gitea 数据目录”中选择 VOS 公共目录或宿主机路径。git/repositories/ 保存裸仓库，gitea/ 保存 LFS、附件、头像等文件；账户、权限、Issue、PR 和 Actions 元数据保存在 PGV 的独立 gitea PostgreSQL 数据库。授权访问该目录的 NAS 用户能直接读取文件，因此应使用专用目录并限制 NAS 目录权限。应用内的仓库授权不会替代 NAS 目录授权。

应用配置与密钥位于 VOS 应用私有存储的 config/。备份时停止应用，同时备份数据目录、私有配置目录与 PGV 的 gitea 数据库；升级保留原路径。公开数据目录不会自动导入已有普通文件夹为 Git 仓库。

完整接口契约与返回值

本机 OpenAPI 3 JSON与上方 Swagger 列出全部原生 REST 接口，包括仓库、文件、分支、Issue、PR、组织、用户、Actions、Webhook、令牌和 SSH 密钥。每个操作展开查看路径参数、查询参数、请求体、响应状态和 Schema；只使用当前安装版本提供的字段，不照搬其他 Gitea 版本的接口。Git、SSH 和 MCP 是独立协议，不使用 REST JSON 响应结构。

请求输入和权限成功返回
GET /api/v1/user无请求体；有效用户凭据。200 User，包括 id（整数）、login（字符串）、full_name（字符串）、is_admin（布尔值）。
GET /api/v1/user/repos?page=1&limit=20page、limit 可选整数；仅返回当前身份可见的仓库。200 Repository[]，空结果为 []；按页读取直至没有下一页。
POST /api/v1/user/reposJSON：必填 name:string；可选 private:boolean、auto_init:boolean、description:string、default_branch:string。原生 PAT 需相应用户写权限；VOS 身份仍受账户与仓库策略约束。201 Repository，包括 id、name、full_name、private、html_url、clone_url、ssh_url。保存返回的实际地址；不要自行拼接用户名和端口。
# 使用自己的 PAT 创建一个私有仓库；请求体不要含凭据
curl --fail-with-body -X POST "$GITEA_URL/api/v1/user/repos" \
  -H "Authorization: token $GITEA_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"api-example","private":true,"auto_init":true,"description":"API example"}'

上述响应字段为常用字段摘录，完整字段、可空性、分页头和每个操作支持的状态以本机 OpenAPI 为准。写操作未声明幂等键；网络中断后先查询仓库/Issue/PR 是否创建成功，再决定是否重试，避免重复创建。原生返回 204 的删除等操作没有正文，不能调用 JSON 解析。文件、归档、Git LFS 与 Actions 日志按响应 Content-Type 读取，不能统一按 JSON 处理。

VOS 会话接口与错误处理

以下路径位于 /app/com.ictrek.gitea 下，是浏览器登录桥使用的接口；外部脚本直接使用 PAT/VOS Bearer 调用原生 API，无需模拟浏览器会话。

操作请求响应
POST /vos/login同源 Origin；JSON access_token:string、可选 locale:string。只接受有效且启用的 VOS 用户。200 {"username":"vos-…","changed":true}，设置 HttpOnly 会话 cookie；changed 表示是否创建或切换会话，不是仓库迁移结果。
GET /vos/session有效 VOS 身份或浏览器 cookie；PAT 不能访问此 VOS 桥接口。200 {"username":"vos-…"}。
POST /vos/locale同源浏览器会话；JSON locale:string，归一化为 zh-CN、zh-TW 或 en-US。204，无正文。
POST /vos/logout同源请求，携带当前 cookie。204，清除浏览器会话，不撤销 PAT/SSH/Runner 凭据。

先检查 HTTP 状态和 Content-Type。网关的 401（缺少/无效身份）、403（同源校验或 VOS 验证失败）、502（原生服务/MCP 不可达）可能返回纯文本；原生 REST 错误通常返回 JSON {"message":"…","url":"…"}。不要按 message 文本匹配错误类型。404 也可能表示当前身份无权查看私有资源；422 应修正请求字段，不能无限重试。失效 VOS token 按 OAuth2 刷新后再试一次；PAT 失效则重新创建或检查权限。读取/连接故障可有界退避重试，写操作必须先核实执行结果。

MCP 客户端先发送 initialize（含其支持的 protocolVersion、capabilities、clientInfo），处理服务端协商的版本，再发送 notifications/initialized、tools/list 和 tools/call。工具名称与 inputSchema 必须从运行中的 tools/list 读取；调用参数为 {"name":"工具名","arguments":{}}，响应可能为 JSON 或 SSE。JSON-RPC 的 error 和工具结果的 isError:true 均表示失败，即使 HTTP 为 200；不能仅凭端口可达判定工具可用。

Endpoints and identity

Browser API: /app/com.ictrek.gitea/api/v1
Same-host applications: http://gitea:8080/app/com.ictrek.gitea/api/v1
Interactive Swagger documentation

Opening Gitea in VOS signs you in and provisions an independent account on first access, using your VOS username when available. Accounts with legacy generated handles move to an available username on their next sign-in. Repositories and credentials stay with the account; update clone URLs from the repository page. Your stable VOS subject owns the account; display name, language and administrator role synchronize on access. Renaming your VOS account preserves repository ownership. Repositories are private by default.

API requests

Use a native Gitea personal access token (PAT), or a VOS user access token for com.ictrek.gitea, obtained through authorization code + PKCE. Browser integrations can use window.vos_platform.api.v1000.oauth2.authorize() and token(), validating state. Refresh expired tokens using the VOS OAuth2 flow. Keep credentials out of source control and logs.

export GITEA_URL='https://<VOS-HOST>:1180/app/com.ictrek.gitea'
curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user"
curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user/repos"

Create a repository with POST /api/v1/user/repos and JSON {"name":"demo","private":true,"auto_init":true}. Refer to Swagger for the remaining API. All external paths include /app/com.ictrek.gitea.

Git over HTTPS

Use the HTTPS clone URL shown in Gitea. Enter your Gitea username and use a native PAT or VOS access token as the password. Keep it in your system credential manager. Git LFS retains its native protocol; browser sign-in uses VOS.

Native PAT and SSH

Create a scoped PAT in Settings → Applications, or add an SSH public key in Settings → SSH / GPG Keys. Keep private keys on your client. Open Code Management once before first use to provision your VOS account.

curl --fail -H "Authorization: token $GITEA_TOKEN" "$GITEA_URL/api/v1/user"
ssh -T -p 32222 git@<VOS-HOST>
git clone ssh://git@<VOS-HOST>:32222/<owner>/<repository>.git

Port 32222 is separate from host administration SSH; change it or the advertised hostname in installation settings. PAT and SSH access for linked users check current VOS account state through the app's platform credential, failing closed on disabled/deleted accounts or verification failure. Revoke individual PATs and keys in Gitea. Browser logout does not revoke these long-lived credentials.

MCP and AI agents

The app also runs the official gitea-mcp server, exposing a stateless HTTP endpoint at /app/com.ictrek.gitea/mcp; inside the same VOS network use http://gitea:8080/app/com.ictrek.gitea/mcp. The gateway checks credentials: Authorization must hold a VOS access token or your own Gitea PAT. The gateway accepts only Bearer, token and Basic; the first two are equivalent. Requests without a valid credential return 401. The server stores no credentials, so permissions follow that user. Only repository, file, branch, pull_request and issue tools are enabled; creating repositories needs write:user on the PAT. Do not send a mismatching Origin header, cross-origin requests are rejected.

# Create a PAT in Settings → Applications first, then probe the endpoint
curl --fail -X POST "http://<VOS-HOST>:1180/app/com.ictrek.gitea/mcp" \
  -H "Authorization: Bearer $GITEA_PAT" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

Actions and runners

Actions is enabled. Set the installation option “Gitea Public URL” to the complete reachable VOS URL for external runners, checkout, job APIs and webhooks; its default is for the same VOS network. Enable it for your repository and obtain a registration token from its Actions → Runners settings, or use organization, user or instance scope. Instance runners require administrator privileges. Run Gitea Runner 5.x on your build machine:

mkdir -p ~/dev/build/gitea-runner
cd ~/dev/build/gitea-runner
gitea-runner register --no-interactive \
  --instance "$GITEA_URL" \
  --token-file "$HOME/.config/gitea/runner-token" \
  --name vos-runner --labels 'vos-linux:host'
gitea-runner daemon

Include /app/com.ictrek.gitea/ in the instance URL. Inside the VOS network use http://gitea:8080/app/com.ictrek.gitea/; external runners need the VOS HTTPS address and certificate trust. Host labels execute in the runner environment and are suitable for trusted repositories; use Docker labels when isolation is needed. See the official runner guide. Persist the secret .runner file.

# .gitea/workflows/ci.yml
name: CI
on: [push, workflow_dispatch]
jobs:
  verify:
    runs-on: vos-linux
    steps:
      - uses: builtin:checkout

Registration tokens, runner machine credentials and user PATs are separate. Registered runners use native repository/organization/instance scope and remain independent of browser sessions. Disable or delete a runner in its Runners settings to revoke it; reset registration tokens separately when needed. Jobs and Secrets follow native Gitea permissions.

Shared storage and backups

Select a VOS public directory or host path during installation. Bare repositories live in git/repositories/; Attachments, LFS and avatars live in gitea/; metadata lives in the dedicated PGV PostgreSQL database gitea. Use a dedicated directory with restrictive NAS permissions: filesystem readers can read repository files independently of Gitea permissions.

Secrets and configuration stay in the application's private config/ storage. Stop the app and back up both directories and the PGV gitea database together. Keep the same paths on upgrades. Existing ordinary directories are not automatically imported as repositories.

Complete API contracts and responses

The local OpenAPI 3 JSON and Swagger above cover all native REST operations: repositories, files, branches, issues, pull requests, organizations, users, Actions, webhooks, tokens and SSH keys. Expand each operation for path/query parameters, request bodies, response codes and schemas. Use the installed version's contract. Git, SSH and MCP use their own protocols rather than the REST JSON format.

RequestInput and permissionSuccessful response
GET /api/v1/userNo body; valid user credential.200 User, including integer id, string login/full_name and boolean is_admin.
GET /api/v1/user/repos?page=1&limit=20Optional integer page/limit; only repositories visible to the caller.200 Repository[]; an empty result is []. Continue paging until no next page remains.
POST /api/v1/user/reposJSON: required name:string; optional private:boolean, auto_init:boolean, description:string, default_branch:string. A PAT needs the appropriate user write scope; VOS callers remain subject to account/repository policy.201 Repository, including id, name, full_name, private, html_url, clone_url and ssh_url. Save returned URLs rather than constructing names or ports.
curl --fail-with-body -X POST "$GITEA_URL/api/v1/user/repos" \
  -H "Authorization: token $GITEA_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"api-example","private":true,"auto_init":true,"description":"API example"}'

These are selected response fields; consult the local OpenAPI for complete fields, nullability, pagination headers and operation-specific status codes. Writes do not declare an idempotency key: after a connection failure, check whether the repository/issue/PR was created before retrying. A 204 response has no body. Read files, archives, Git LFS and Actions logs according to their Content-Type rather than parsing every response as JSON.

VOS session API and error handling

The following paths are relative to /app/com.ictrek.gitea and serve the browser login bridge. External scripts should call the native API with a PAT or VOS Bearer token directly.

OperationRequestResponse
POST /vos/loginSame-origin Origin; JSON access_token:string, optional locale:string; the VOS user must be valid and enabled.200 {"username":"vos-…","changed":true}, plus an HttpOnly session cookie. changed describes session creation/switching, not repository migration.
GET /vos/sessionValid VOS identity or browser session cookie; a PAT cannot access this VOS bridge operation.200 {"username":"vos-…"}.
POST /vos/localeSame-origin browser session; JSON locale:string, normalized to zh-CN, zh-TW or en-US.204, no body.
POST /vos/logoutSame-origin request with the current cookie.204; clears the browser session, not PAT/SSH/runner credentials.

Inspect HTTP status and Content-Type first. Gateway 401 (missing/invalid identity), 403 (origin or VOS validation failure) and 502 (native service/MCP unavailable) can have plain-text bodies. Native REST errors normally contain JSON {"message":"…","url":"…"}; do not classify errors by message text. 404 can also hide a private resource from an unauthorized caller; correct invalid fields for 422 rather than retrying indefinitely. Refresh an expired VOS token through OAuth2 and retry once; replace/review an invalid PAT. Use bounded backoff for reads and connection failures, and reconcile write outcomes before retrying.

MCP clients send initialize with their supported protocolVersion, capabilities and clientInfo, negotiate the returned version, then send notifications/initialized, tools/list and tools/call. Discover tool names and inputSchema from the running server; call with {"name":"tool-name","arguments":{}}. Responses can be JSON or SSE. JSON-RPC error and tool results with isError:true are failures even with HTTP 200; reachability alone does not prove a working tool.
