从 VOS 打开应用后自动登录。首次访问优先使用 VOS 用户名创建独立 Gitea 账户。旧版自动生成的用户名会在下次登录时迁移到可用的用户名，仓库和凭据继续保留；请按仓库页面更新克隆地址。之后按 VOS 的稳定用户 ID 同步显示名、管理员角色与语言；VOS 中改名不会改变仓库归属。普通用户仅能访问自己或被授权的仓库，系统管理员拥有 Gitea 管理权限。

调用 API

外部客户端可以使用原生 Gitea PAT，或使用 VOS 为 com.ictrek.gitea 签发的用户 access token。通过 VOS OAuth2 authorization code + PKCE 获取，令牌到期后按 VOS OAuth2 流程刷新。浏览器插件可调用 window.vos_platform.api.v1000.oauth2.authorize() 和 token()，并校验 state。不要将令牌写入仓库或日志。

export GITEA_URL='https://<VOS地址>:1180/app/com.ictrek.gitea'
# VOS_ACCESS_TOKEN 由你的 OAuth2 客户端提供
curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user"

curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user/repos"

创建仓库：POST /api/v1/user/repos，JSON 示例 {"name":"demo","private":true,"auto_init":true}。仓库默认私有。更多接口使用上方 Swagger，路径前缀始终为 /app/com.ictrek.gitea。

Git HTTPS

使用页面给出的 HTTPS clone URL；用户名填写 Gitea 用户名，密码可使用原生 PAT 或 VOS access token。建议使用系统凭据管理器，不把令牌写入 URL。Git LFS 保留 Gitea 原生协议。浏览器登录统一走 VOS，无需第二套登录密码。

原生 PAT 与 SSH 密钥

在用户设置 → 应用创建个人访问令牌，选择所需权限；令牌只显示一次。在用户设置 → SSH / GPG 密钥添加自己的 SSH 公钥，私钥留在客户端。

# GITEA_TOKEN 为你自己创建的原生 PAT
curl --fail -H "Authorization: token $GITEA_TOKEN" \
  "$GITEA_URL/api/v1/user"

# 默认 SSH 端口为 32222，用户名固定为 git
ssh -T -p 32222 git@<VOS设备IP或域名>
git clone ssh://git@<VOS设备IP或域名>:32222/<仓库所有者>/<仓库名>.git

SSH 独立于宿主机管理用的 22 端口，安装参数可调整端口与外部域名；仓库页面会生成 clone 地址。首次使用先访问一次代码管理完成 VOS 账户创建。VOS 关联账户的 PAT 和 SSH 操作会通过应用专属平台凭据查询该用户的最新状态；用户被禁用、删除或平台校验不可用时拒绝访问。PAT 与 SSH 密钥也可分别在 Gitea 中撤销；VOS 退出浏览器会话不等于撤销这些长期凭据。

MCP 与 AI Agent

应用同时运行官方 gitea-mcp 服务，在 /app/com.ictrek.gitea/mcp 提供无状态 HTTP 端点；同一 VOS 网络内使用 http://gitea:8080/app/com.ictrek.gitea/mcp。端点由网关校验凭据，必须携带 Authorization: Bearer，值为 VOS access token 或自己的 Gitea PAT；两种都无效时返回 401，无凭据不能调用。服务端不保存令牌，权限按该用户生效。只开放 repository、file、branch、pull_request、issue 五类工具；创建仓库需要 PAT 包含 write:user。不要附加不匹配的 Origin 头，跨站来源会被拒绝。

# 先在“用户设置 → 应用”创建 PAT，然后初始化 MCP 会话
curl --fail -X POST "http://<VOS设备IP或域名>:1180/app/com.ictrek.gitea/mcp" \
  -H "Authorization: Bearer $GITEA_PAT" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

Actions 与 Runner

Actions 已开启。外部 Runner 使用前，请在安装配置“Gitea 对外访问地址”填写完整的 VOS 可达地址，供 checkout、任务 API 与 Webhook 使用；默认值适合同一 VOS 网络。先在仓库设置启用 Actions，再从“仓库 / 组织 / 用户 / 实例设置 → Actions → Runners”取得相应作用域的注册令牌。实例级 runner 需要管理员权限。Runner 在构建机独立运行，不会自动占用 VOS 容器的构建环境。

mkdir -p ~/dev/build/gitea-runner
cd ~/dev/build/gitea-runner
# 先安装 Gitea Runner 5.x；将注册令牌存入仅自己可读的文件
gitea-runner register --no-interactive \
  --instance "$GITEA_URL" \
  --token-file "$HOME/.config/gitea/runner-token" \
  --name vos-runner --labels 'vos-linux:host'
gitea-runner daemon

--instance 必须包含 /app/com.ictrek.gitea/，并能被 runner 和任务环境访问；同一 VOS 网络可用 http://gitea:8080/app/com.ictrek.gitea/。外部机器使用 VOS 的 HTTPS 地址并信任其证书。示例 host 标签直接在 runner 环境执行，仅用于可信仓库；需要容器隔离时按官方 Runner 文档配置 Docker 标签。持久保存 .runner，它包含机器凭据。

仓库中添加 .gitea/workflows/ci.yml：

name: CI
on: [push, workflow_dispatch]
jobs:
  verify:
    runs-on: vos-linux
    steps:
      - uses: builtin:checkout
      - run: echo 'VOS Gitea Actions ready'

注册令牌用于新增 runner，机器凭据用于轮询任务，均不同于用户 PAT。注册后的 runner 按仓库 / 组织 / 实例作用域独立管理，不随浏览器退出而停止；撤销时需在相应 Runners 页面禁用或删除 runner，必要时重置注册令牌。任务与 Secrets 的权限遵循 Gitea 原生规则。

公共目录与备份

安装时在“Gitea 数据目录”中选择 VOS 公共目录或宿主机路径。git/repositories/ 保存裸仓库，gitea/ 保存 LFS、附件、头像等文件；账户、权限、Issue、PR 和 Actions 元数据保存在 PGV 的独立 gitea PostgreSQL 数据库。授权访问该目录的 NAS 用户能直接读取文件，因此应使用专用目录并限制 NAS 目录权限。应用内的仓库授权不会替代 NAS 目录授权。

应用配置与密钥位于 VOS 应用私有存储的 config/。备份时停止应用，同时备份数据目录、私有配置目录与 PGV 的 gitea 数据库；升级保留原路径。公开数据目录不会自动导入已有普通文件夹为 Git 仓库。

API integration guide

Connect repositories, scripts and applications using your VOS identity.

Endpoints and identity

Browser API: /app/com.ictrek.gitea/api/v1
Same-host applications: http://gitea:8080/app/com.ictrek.gitea/api/v1
Interactive Swagger documentation

Opening Gitea in VOS signs you in and provisions an independent account on first access, using your VOS username when available. Accounts with legacy generated handles move to an available username on their next sign-in. Repositories and credentials stay with the account; update clone URLs from the repository page. Your stable VOS subject owns the account; display name, language and administrator role synchronize on access. Renaming your VOS account preserves repository ownership. Repositories are private by default.

API requests

Use a native Gitea personal access token (PAT), or a VOS user access token for com.ictrek.gitea, obtained through authorization code + PKCE. Browser integrations can use window.vos_platform.api.v1000.oauth2.authorize() and token(), validating state. Refresh expired tokens using the VOS OAuth2 flow. Keep credentials out of source control and logs.

export GITEA_URL='https://<VOS-HOST>:1180/app/com.ictrek.gitea'
curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user"
curl --fail -H "Authorization: Bearer $VOS_ACCESS_TOKEN" \
  "$GITEA_URL/api/v1/user/repos"

Create a repository with POST /api/v1/user/repos and JSON {"name":"demo","private":true,"auto_init":true}. Refer to Swagger for the remaining API. All external paths include /app/com.ictrek.gitea.

Git over HTTPS

Use the HTTPS clone URL shown in Gitea. Enter your Gitea username and use a native PAT or VOS access token as the password. Keep it in your system credential manager. Git LFS retains its native protocol; browser sign-in uses VOS.

Native PAT and SSH

Create a scoped PAT in Settings → Applications, or add an SSH public key in Settings → SSH / GPG Keys. Keep private keys on your client. Open Code Management once before first use to provision your VOS account.

curl --fail -H "Authorization: token $GITEA_TOKEN" "$GITEA_URL/api/v1/user"
ssh -T -p 32222 git@<VOS-HOST>
git clone ssh://git@<VOS-HOST>:32222/<owner>/<repository>.git

Port 32222 is separate from host administration SSH; change it or the advertised hostname in installation settings. PAT and SSH access for linked users check current VOS account state through the app's platform credential, failing closed on disabled/deleted accounts or verification failure. Revoke individual PATs and keys in Gitea. Browser logout does not revoke these long-lived credentials.

MCP and AI agents

The app also runs the official gitea-mcp server, exposing a stateless HTTP endpoint at /app/com.ictrek.gitea/mcp; inside the same VOS network use http://gitea:8080/app/com.ictrek.gitea/mcp. The gateway checks credentials: Authorization: Bearer must hold a VOS access token or your own Gitea PAT. Requests without a valid credential return 401. The server stores no credentials, so permissions follow that user. Only repository, file, branch, pull_request and issue tools are enabled; creating repositories needs write:user on the PAT. Do not send a mismatching Origin header, cross-origin requests are rejected.

# Create a PAT in Settings → Applications first, then probe the endpoint
curl --fail -X POST "http://<VOS-HOST>:1180/app/com.ictrek.gitea/mcp" \
  -H "Authorization: Bearer $GITEA_PAT" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

Actions and runners

Actions is enabled. Set the installation option “Gitea Public URL” to the complete reachable VOS URL for external runners, checkout, job APIs and webhooks; its default is for the same VOS network. Enable it for your repository and obtain a registration token from its Actions → Runners settings, or use organization, user or instance scope. Instance runners require administrator privileges. Run Gitea Runner 5.x on your build machine:

mkdir -p ~/dev/build/gitea-runner
cd ~/dev/build/gitea-runner
gitea-runner register --no-interactive \
  --instance "$GITEA_URL" \
  --token-file "$HOME/.config/gitea/runner-token" \
  --name vos-runner --labels 'vos-linux:host'
gitea-runner daemon

Include /app/com.ictrek.gitea/ in the instance URL. Inside the VOS network use http://gitea:8080/app/com.ictrek.gitea/; external runners need the VOS HTTPS address and certificate trust. Host labels execute in the runner environment and are suitable for trusted repositories; use Docker labels when isolation is needed. See the official runner guide. Persist the secret .runner file.

# .gitea/workflows/ci.yml
name: CI
on: [push, workflow_dispatch]
jobs:
  verify:
    runs-on: vos-linux
    steps:
      - uses: builtin:checkout
      - run: echo 'VOS Gitea Actions ready'

Registration tokens, runner machine credentials and user PATs are separate. Registered runners use native repository/organization/instance scope and remain independent of browser sessions. Disable or delete a runner in its Runners settings to revoke it; reset registration tokens separately when needed. Jobs and Secrets follow native Gitea permissions.

Shared storage and backups

Select a VOS public directory or host path during installation. Bare repositories live in git/repositories/; Attachments, LFS and avatars live in gitea/; metadata lives in the dedicated PGV PostgreSQL database gitea. Use a dedicated directory with restrictive NAS permissions: filesystem readers can read repository files independently of Gitea permissions.

Secrets and configuration stay in the application's private config/ storage. Stop the app and back up both directories and the PGV gitea database together. Keep the same paths on upgrades. Existing ordinary directories are not automatically imported as repositories.
